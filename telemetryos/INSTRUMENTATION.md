- qr-not-a-noop (`app/main.py`): application.add_middleware(TelemetryMiddleware) is called from instrument_app AFTER the app has already been fully built and, more importantly, add_event_handler/include_router have run. However the ordering comment is wrong — TelemetryMiddleware added last runs OUTERMOST (executes first / before the OTel span). Starlette builds the middleware stack in LIFO so the middleware added last wraps the others, meaning TelemetryMiddleware runs OUTSIDE the FastAPIInstrumentor server span, so trace.get_current_span() in the finally block returns the non-recording INVALID_SPAN and the slow_request event is silently dropped.
- qr-not-a-noop (`app/core/telemetry.py`): OTLPSpanExporter/OTLPMetricExporter are constructed unconditionally with endpoint=OTLP_ENDPOINT, which is None when OTEL_EXPORTER_OTLP_ENDPOINT is unset (telemetryCollection is 'none').
