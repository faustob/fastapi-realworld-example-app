**Auto-fixed during review (7):**
- qr-endpoint-env-driven (`app/telemetry.py`): Hardcoded OTLP endpoint "http://localhost:4317" — wrong in every real deployment.
- qr-not-a-noop (`app/telemetry.py`): The module-level `_meter = metrics.get_meter(__name__)` and all instruments are created at import time. In Python's OTel, get_meter() captures the provider at call time; if this module is imported (e.g. transitively via app.main importing app.telemetry, or app.api.routes.authentication importing it) before setup_telemetry() registers the real MeterProvider, the meter binds to the no-op provider and all counters/histograms silently emit nothing.
- qr-preserves-behavior (`app/main.py`): The unhandled_exception_handler registered for the base `Exception` re-raises `exc` instead of returning a response. FastAPI/Starlette exception handlers are expected to return a Response; raising from within the handler changes error-handling behavior and can result in the exception propagating differently (500 handling) than the framework's default, altering the app's response semantics.
- qr-not-a-noop (`app/main.py`): `trace.StatusCode.ERROR` is not a valid attribute; the status code enum is `opentelemetry.trace.StatusCode` but span status should be set via `Status(StatusCode.ERROR, ...)`. As written `span.set_status(trace.StatusCode.ERROR, str(exc))` uses an incorrect API surface and will not set status correctly.
- qr-not-a-noop (`app/api/dependencies/authentication.py`): The module-level instruments in app/telemetry.py are initialised to None and only assigned inside _init_instruments(), which runs from setup_telemetry(). Because authentication.py does `from app.telemetry import auth_attempts`, it binds the name at import time to the None object; even after setup_telemetry() reassigns the module attribute, this module's local `auth_attempts` still references None, so `auth_attempts.add(...)` raises AttributeError at runtime.
- qr-not-a-noop (`app/api/routes/authentication.py`): authentication.py imports auth_attempts, flow_duration, flow_entry_counter, flow_outcomes, flow_validation_outcomes via `from app.telemetry import ...`, binding them to None at import time. Since _init_instruments() only rebinds the app.telemetry module attributes, these local names remain None and every `.add()`/`.record()` call raises AttributeError, crashing the login/register handlers.
- qr-not-a-noop (`app/main.py`): app/main.py does `from app.telemetry import active_requests, setup_telemetry`, binding active_requests to None before setup_telemetry() runs. The track_active_requests middleware then calls `active_requests.add(1)` on None, raising AttributeError on every HTTP request.
