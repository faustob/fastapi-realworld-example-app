**Auto-fixed during review (4):**
- qr-not-a-noop (`app/core/telemetry.py`): trace.set_tracer_provider() and metrics.set_meter_provider() do not raise on double-registration; they log a warning and keep the FIRST provider. The try/except blocks provide no real guard, but more importantly if a provider is already the default no-op it will be kept. However the actual defect: since no agent registers under app-sdk, the providers ARE set here, so this works — but wrapping set_*_provider in a bare except that swallows exporter construction errors means a failed OTLPMetricExporter build silently leaves instruments bound to the no-op provider, emitting nothing.

- qr-not-a-noop (`app/core/telemetry.py`): setup_telemetry unconditionally builds and registers a new TracerProvider and MeterProvider via set_tracer_provider/set_meter_provider despite the docstring claiming existing providers are kept; the OTel SDK will keep the first-registered provider and log an 'Overriding of current ... is not allowed' warning, but the code never actually checks for or reuses an existing provider so its stated multi-call safety is false and re-invocation is not idempotent.
**Outstanding (2):**
- ⚠ qr-endpoint-env-driven (`app/core/telemetry.py`:61): Hardcoded OTLP endpoint "http://localhost:4318" — wrong in every real deployment. — _Read the endpoint from OTEL_EXPORTER_OTLP_ENDPOINT / config instead of a literal._
- ⛔ qr-not-a-noop (`app/core/telemetry.py`:66): The provider construction is wrapped in try/except, but trace.set_tracer_provider() / metrics.set_meter_provider() do NOT raise when a provider is already set — they log a warning and silently keep the existing one. The try/except therefore never triggers a fallback, and more importantly since existingRegistrationFiles is empty and this is the only bootstrap, the guards are cosmetic; but the real defect is that if set_meter_provider is a no-op because one was already set, the instruments still bind via get_meter to whatever is registered — acceptable. However, the OTLP exporter default protocol assumption combined with no collector (telemetryCollection: none) means the http exporter targets localhost:4318 which does not exist, so nothing is actually collected. — _Remove the misleading try/except double-registration guards (they cannot catch already-set providers) and rely on a single deterministic registration at startup._
