- qr-not-a-noop (`app/core/telemetry.py`): The tracer setup's except clause checks if the current provider class name is not 'TracerProvider' — but a fresh, never-registered global provider is the SDK-less API's ProxyTracerProvider (not 'TracerProvider'), so a real OTLPSpanExporter construction failure would be re-raised correctly, yet if set_tracer_provider itself logs-and-ignores a duplicate (OTel-JS/Python only WARN, they do not raise) the try never throws; more critically the class-name string check is fragile and will re-raise on any genuine exporter misconfiguration only when no provider was set, defeating the intended 'tolerate already-set' path. Under app-sdk with no agent, nothing else registers a provider, so this defensive branch is dead and any exporter init failure aborts startup.
- qr-preserves-behavior (`app/main.py`): The added Exception handler registered via @application.exception_handler(Exception) re-raises exc, changing behavior: previously unhandled exceptions were handled by Starlette's default ServerErrorMiddleware (500 response); now an app-level handler that raises inside the handler chain changes error propagation/response semantics for all unhandled exceptions.
- qr-preserves-behavior (`app/main.py`): The unhandled exception handler uses trace.StatusCode.ERROR, but Status/StatusCode live in opentelemetry.trace.status (accessible as trace.StatusCode only if re-exported); more importantly set_status expects a Status object or StatusCode with description as second arg — trace.StatusCode is not imported here and this attribute access risks AttributeError.
- qr-not-a-noop (`app/core/telemetry.py`): set_tracer_provider and set_meter_provider are wrapped in try/except that swallows the SDK-already-set warning, but they never raise on an already-set provider (they only log); the real risk is the broad except silently discarding an OTLPSpanExporter/OTLPMetricExporter construction failure, leaving the provider registered with no working exporter so telemetry is silently dropped.
**Outstanding (1):**
- ⚠ qr-not-a-noop (`app/core/telemetry.py`:45): trace.set_tracer_provider / metrics.set_meter_provider do not raise when a provider is already registered — OTel-Python logs a warning and keeps the FIRST provider. The try/except is dead code and, if a provider were already set, the instruments would be created from the app's new (unregistered) provider while the global stays the old one, silently dropping metrics. — _Remove the try/except; set the providers unconditionally at startup (app-sdk owns registration). Do not create instruments from a provider that may not be the global one._
